# Research: 今日読める図書館の検索

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-10-21

## R1. 所蔵状況の取得元

- **Decision**: カーリル 図書館API（`https://api.calil.jp/check`）を使う。
- **Rationale**:
  - 日本全国の公共図書館の所蔵・貸出状況を、ISBN と図書館システムID（systemid）を
    カンマ区切りで複数指定して1セッションで取得できる。spec の「全国対応」（Clarification Q2）に合う。
  - 応答は JSON（UTF-8）で、標準ライブラリだけで扱える。
- **Alternatives considered**:
  - 各館の OPAC を個別にスクレイピングする: 館ごとに実装が必要で、規約・robots.txt の確認も
    館ごとに発生するため不採用（原則 I・技術的制約）。
  - 国立国会図書館サーチの所蔵情報: 貸出状況（在架/貸出中）が得られないため不採用。
- **利用条件（実装に反映する事項）**:
  - アプリケーションキーが必須 → 環境変数 `LIBREAD_CALIL_APPKEY` から読む。リポジトリに含めない。
  - 上限は1時間あたり1,000ブックリクエスト（1 ISBN × 1 図書館システム = 1）、
    1セッション最大100ブックリクエスト。
    想定規模（本5冊 × 最大10システム = 50）なら1回の検索は1セッションに収まる。
  - ポーリング: 初回応答の `continue` が `1` なら、`session` を付けて再度問い合わせる。
    間隔は2秒以上空ける。
  - 図書館名・貸出状況を表示する場合はカーリルへのリンクが必須 →
    検索結果に本ごとに `https://calil.jp/book/<ISBN>` を表示する。

## R2. 所蔵状況の分類（FR-003 への対応付け）

カーリルの館別ステータス（`libkey` の値）を、spec の分類へ次のように対応付ける。
未知の値は必ず「不明」とする（原則 III・IV）。

| カーリルの値 | spec の分類 | 読める |
|---|---|---|
| 貸出可 | 在架（貸出可） | ○ |
| 館内のみ | 在架（館内閲覧のみ） | ○ |
| 貸出中 | 貸出中 | × |
| 予約中 | 予約中（カーリルの値をそのまま表示） | × |
| 蔵書なし / 図書館システム側の応答に館がない（システムの status が OK・Cache の場合） | 所蔵なし | × |
| 蔵書あり（貸出状況不明）/ 準備中 / 休館中 / その他の独自値 | 不明 | × |
| システムの status が Error、またはタイムアウトで Running のまま | 不明 | × |

- 「不明」の場合は、カーリルが返した元の値を併記して理由が分かるようにする。
- 複数冊の所蔵（spec Edge Case）: カーリルが館単位にまとめて状態を返すため、libread 側では扱わない。

## R3. 本の検索（書名 → ISBN）

- **Decision**: 国立国会図書館サーチ OpenSearch API（`https://ndlsearch.ndl.go.jp/api/opensearch`）を
  `title` / `isbn` / `creator` / `publisher` / `cnt` パラメータで使う。応答の RSS（XML）は `encoding/xml` で読む。
- **Rationale**: キー不要で、国内の書誌（ISBN・書名・著者・出版社）の網羅性が高い。
  カーリルには書名検索がない。
- **Alternatives considered**: Google Books API は国内書籍の ISBN 欠落が多いため不採用。
  openBD は ISBN から書誌を引く用途のみで、書名検索ができないため不採用。
- **Note**: 応答 XML 内で ISBN・著者がどの要素に入るかは、DC-NDL 形式の仕様書と
  実際の応答で確かめる。実装時に実応答を `testdata/` に記録し、テストはその記録を使う（原則 II）。
  - **確認結果 (2026-10-29)**: 書名は `dc:title`、著者は `dc:creator`（典拠形「姓, 名, 生没年」、複数あり）、
    出版社は `dc:publisher`（複数あり）、ISBN は `dc:identifier xsi:type="dcndl:ISBN"`（10桁・ハイフン付きのこともある）に入る。
    `dcndl:ISBN13` にも10桁の値が入ることがあるため、ISBN は `dcndl:ISBN` から読んで13桁に正規化する。
    ISBN のない記録（古い全集など）も返る。
  - **検索結果の並び (2026-10-29)**: OpenSearch も SRU も、結果を書名の読み（`dcndl:titleTranscription`）の五十音順で返す。
    `sort`・`mediatype`、SRU の `title exact`・`sortBy` を指定しても順序は変わらなかった。
    `title` は収録作品名にも一致するため、`title=吾輩は猫である` は345件になり、本体（読み「ワガハイ…」）は末尾近くに来る。
    全345件を1回で取ると 1.1MB・46秒かかり、使えない。`creator=夏目漱石&publisher=岩波書店` を足すと15件まで絞れる。
    応答時間は同じ要求でも2秒〜40秒程度ばらつく。
  - **Decision（並べ替えと絞り込み）**: 1回の要求で `cnt=20` を取得し、libread 側で「書名の完全一致 → 前方一致 → その他」の順に
    安定ソートして上位10件を表示する。`book find` に `--author`・`--publisher` を設け、`creator`・`publisher` に渡す。
    一致件数（`openSearch:totalResults`）が表示件数より多ければ、絞り込みと ISBN での検索を案内する（contracts/cli.md）。
    取得件数を増やすほど応答が遅くなるので、20件（絞り込んだ検索が1回で収まる程度）にとどめる。
  - **Decision（タイムアウト）**: NDL サーチへの要求だけ、タイムアウトを30秒にする（他のサービスは10秒のまま）。
    応答時間は件数よりサーバー側の混み具合で決まり、20件でも10件でも10秒を超えることがあった（2026-10-29 の測定）。
- **データプロバイダの限定**: `dpid=iss-ndl-opac`（国立国会図書館の蔵書）を指定し、
  メタデータの利用条件が1つのプロバイダの条件だけになるようにする（R10）。
  国内出版物は納本制度により国立国会図書館が網羅的に所蔵しているので、検索の網羅性は保てる。
- **出典表示**: NDL サーチの API を使っていることを、`book find` と `book add` の出力、および `help` に表示する（R10）。

## R4. 祝日の判定（FR-016「祝日の扱い」）

- **Decision**: holidays-jp API（`https://holidays-jp.github.io/api/v1/{year}/date.json`）を、
  年ごとにキャッシュして使う。キャッシュは30日で更新する。
- **Rationale**: JSON で、キー不要、MIT ライセンス。前年・今年・翌年を提供している。
- **データの出典**: Google カレンダーの祝日情報から自動生成されたもので、公的機関（内閣府）の一次データではない。
  祝日の判定は、このデータの正しさに依存する。
- **取得範囲外の日付**: 前年・今年・翌年以外の年は取得できない。取得できない年の日付は
  「祝日か判定できない」（`known=false`）とし、data-model.md の `HolidayUnknown` に合わせる。
  libread が判定するのは「今日」だけなので、通常は取得範囲内に収まる。
- **Alternatives considered**:
  - 内閣府の祝日 CSV: Shift_JIS のため外部の文字コード変換パッケージが必要になり不採用（原則 I）。
  - 祝日一覧をソースに埋め込む: 毎年の更新作業が要るため不採用。
- **Failure mode**: 祝日データが取得できずキャッシュもない場合、その日が祝日かどうかが分からない。
  祝日の扱いが曜日と異なる館は「開館情報不明（祝日判定不可）」として「読める」に含めない（原則 IV）。

## R5. 開館スケジュールの表現

- **Decision**: 曜日ごとに「休館」または「開館 HH:MM–閉館 HH:MM」を1区間で持つ。祝日の扱いは
  「曜日どおり」「休館」「独自の時間」の3種類から選ぶ。それ以外の例外は臨時休館期間で入力してもらう。
- **Rationale**: 「第3月曜休館」「祝日の翌日休館」のような規則をすべて表すと入力も実装も複雑になる。
  利用者が期間で入力すれば足りるので、規則としては扱わない（原則 I）。
- **Alternatives considered**: iCalendar の RRULE 相当の規則表現。入力が難しいため不採用。

## R6. データの保存とキャッシュ

- **Decision**:
  - 利用者データ（読みかけの本・利用図書館・開館スケジュール・臨時休館期間）は1つの JSON ファイルに保存する。
    場所は `os.UserConfigDir()/libread/data.json` で、環境変数 `LIBREAD_DATA_DIR` で変えられる。
  - キャッシュ（所蔵状況・祝日）は `os.UserCacheDir()/libread/` に置く。
  - 書き込みは一時ファイルに書いてから rename する（途中で落ちてもファイルが壊れない）。
- **Rationale**: 利用者は1人で、データ量も小さい（本・図書館とも数十件）。データベースは要らない（原則 I）。
- **Alternatives considered**: SQLite は外部ドライバか cgo が必要になり、この規模では過剰なため不採用。

## R7. 鮮度と時間制限

- 所蔵キャッシュの有効期間は30分（spec Assumptions）。期限内ならキャッシュを使い、取得日時を表示する。
- 期限切れのキャッシュは再取得する。再取得に失敗した場合は「不明（古い情報: HH:MM 取得）」と表示し、
  「読める」には含めない（FR-007、原則 IV）。
- SC-002（10秒以内）を満たすため、カーリルへの問い合わせ全体（ポーリング込み）に8秒の上限を設ける。
  8秒を過ぎても Running の図書館システムは「不明（取得タイムアウト）」とする。
- 時刻は `Asia/Tokyo` で扱う。どの環境でもタイムゾーン情報を読めるよう `time/tzdata` を埋め込む。

## R8. CLI とツール類

- **Decision**:
  - CLI は標準ライブラリの `flag` パッケージでサブコマンドを実装する。
  - `staticcheck` は `go.mod` の `tool` ディレクティブでバージョンを固定し、`go tool staticcheck` で実行する。
- **Rationale**: サブコマンドは十数個で、cobra などのフレームワークは要らない（原則 I）。
  `tool` ディレクティブは Go 1.24 以降の標準機能。
- **Alternatives considered**: spf13/cobra。依存が増えるわりに、得られるのはヘルプ生成程度のため不採用。

## R9. 外部サービスへの配慮（技術的制約）

1回のコマンド実行で各サービスへ送るリクエストの上限を、次のように決める。
コマンドは1回で終わり常駐しないので、この上限とキャッシュがそのまま流量の制限になる。

| サービス | 1回のコマンドでの上限 | 間隔 | キャッシュ |
|---|---|---|---|
| カーリル 所蔵チェック | 1セッション（初回 + ポーリング、8秒以内） | ポーリングは2秒以上 | 30分（`holdings.json`） |
| カーリル 図書館検索 | 1リクエスト（`lib find` / `lib add`） | — | なし |
| NDL サーチ | 1リクエスト（`book find` / `book add`） | — | なし |
| holidays-jp | 年ごとに1リクエスト（キャッシュが30日を過ぎたときだけ） | — | 30日（`holidays-YYYY.json`） |

- カーリルの1時間1,000ブックリクエストの上限: 1回の `check` は最大50ブックリクエスト（本5冊 × 10システム）。
  30分以内の再実行はキャッシュを使うので、通常の使い方で上限に届くことはない。
  そのため、1時間あたりの回数を数える仕組みは作らない（原則 I）。
- 各サービスへの同時リクエストは1本までとする。
- すべてのリクエストに `User-Agent: libread/<version>` を付ける。
- 上の上限はテストで確かめる（tasks.md T042: コマンドごとの送信回数を検証する）。
- 利用者のメモ（読んだ位置）はどの外部サービスにも送らない。
  外部に送るのは ISBN、図書館システムID、書名検索語、年のみ。
