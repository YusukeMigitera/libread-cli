# Quickstart: 今日読める図書館の検索

**Feature**: [spec.md](./spec.md) | **CLI**: [contracts/cli.md](./contracts/cli.md)

この機能が端から端まで動くことを確かめる手順。

## 前提

- Go 1.25 以上
- カーリルのアプリケーションキー（カーリルの開発者ダッシュボードで取得）。
  手順 2 と 3 で使う。手順 1 には不要。

## 1. 品質ゲート（ネットワーク不要）

```sh
gofmt -l .               # 何も出力されないこと
go vet ./...
go tool staticcheck ./...
go test ./...            # 記録済みレスポンスだけを使い、実ネットワークには接続しない
```

**期待結果**: すべて警告なしで成功する。

## 2. 実データでの確認

検証用に専用のデータ置き場を使い、普段のデータを汚さないようにする。

```sh
export LIBREAD_CALIL_APPKEY=<your key>
export LIBREAD_DATA_DIR="$(mktemp -d)"
go build -o ./bin/libread ./cmd/libread

# 利用図書館の登録（User Story 3）
./bin/libread lib find --pref 東京都 --city 世田谷区
./bin/libread lib add <表示された SystemID:LibKey>
./bin/libread lib hours <図書館> --sun 09:00-17:00 --mon closed \
  --tue 09:00-19:00 --wed 09:00-19:00 --thu 09:00-19:00 --fri 09:00-19:00 --sat 09:00-17:00 \
  --holiday same

# 読みかけの本の登録（User Story 2）
./bin/libread book find 吾輩は猫である --author 夏目漱石 --publisher 岩波書店
./bin/libread book add <表示された ISBN> --note "p.120まで"

# 検索（User Story 1）
./bin/libread
```

**期待結果**:

- 開館中で在架の館が「■ 今日読める図書館」に表示される。
- 表示内容がカーリルの書籍ページ（出力に表示される URL）の状況と一致する。
- 所蔵の取得日時と、開館情報の「利用者入力」表記・最終更新日が表示される。

## 3. 境界条件の確認

| 操作 | 期待結果 |
|---|---|
| `lib closure add <図書館> <今日> <今日>` の後に `libread` | その館が「休館（期間）」になり、読めない側に表示される |
| 開館スケジュールを入力していない館を `lib add` した後に `libread` | 「開館情報未入力」と表示される |
| 30分以内に `libread` をもう一度実行 | 同じ取得日時が表示される（キャッシュを利用し、再取得しない） |
| `LIBREAD_CALIL_APPKEY` を外して `libread` | 終了コード 1 で、キーの設定方法が案内される |
| `libread check <ISBN>` | その本だけが対象になる |

時刻に依存する条件（閉館後、閉館まで30分未満、祝日、取得タイムアウト）は、
現在時刻と外部応答を差し替えた自動テストで確かめる（手順 1 の `go test`）。

## 実サービスでの確認結果（T044、2026-10-30 01:05〜01:10 JST）

手順 2・3 を、一時的な `LIBREAD_DATA_DIR`・`LIBREAD_CACHE_DIR` を使って実際のカーリル・NDL サーチに対して実行した。
期待結果と食い違う動作はなかった。手順どおりに進めたときに気づいた違いと注意点を記録する。

| 項目 | 結果 |
|---|---|
| `lib find --pref 東京都 --city 世田谷区` | 35館（世田谷区立21館と区内の大学図書館など）。記録済みの `library_setagaya.json` と同じ |
| `lib add`・`lib hours` | 期待どおり。最終更新日は実行日（2026-10-30）になった |
| `book find 吾輩は猫である --author 夏目漱石 --publisher 岩波書店` | 6件。1件目が 9784003101018（岩波文庫） |
| `book add 9784003101018 --note "p.120まで"` | 最初の2回は NDL サーチが応答せず、30秒のタイムアウトで終了コード `1` になった。数分後に再実行すると 0.4秒で成功した（下記） |
| `libread`（初回） | 約3秒で表示。カーリルの書籍ページの状況と一致した |
| 臨時休館を今日で追加して `libread` | その館が「休館（検証 2026-10-30〜2026-10-30）」になり、読めない側に表示された |
| 開館スケジュール未入力の館 | 「開館情報未入力」と表示された |
| 30分以内に再実行 | 同じ取得日時（01:09）が表示され、再取得しなかった（約0.01秒） |
| `LIBREAD_CALIL_APPKEY` を外して実行 | 終了コード `1` で、キーの設定方法が案内された |
| `libread check 9784003101018` | その本だけが対象になった |

手順の注意点:

- **登録する館によっては「読める」館が出ない**: 9784003101018 は世田谷区では梅丘・世田谷・喜多見の各館だけが所蔵しており、
  手順 2 の例どおり中央図書館だけを登録すると「所蔵なし」になる。
  「■ 今日読める図書館」を確かめるには、`libread` の出力に表示されるカーリルの書籍ページで所蔵館を確認し、その館を登録する
  （今回は梅丘図書館を追加して「在架（貸出可）」を確認した）。
- **実行する時刻で表示が変わる**: 深夜に実行したため、開館日の館は「開館中」ではなく「開館前 09:00〜19:00」と表示された。
  開館前の館も今日行けば読めるので「■ 今日読める図書館」に含まれる。
- **NDL サーチの応答が一時的に返らないことがある**: ISBN での検索（`book add` と `book find <ISBN>`）が2回続けて
  30秒のタイムアウトになり、その間も curl では同じ URL に1秒未満で応答があった。数分後には libread からも
  すぐに応答があり、再現しなかった。HTTP/2 の接続で応答ヘッダーが返らなかったもので、確認環境の中継プロキシか
  NDL 側の一時的な問題と考えられる。失敗しても終了コード `1` と原因を表示して終わるので、再実行すればよい。
- **祝日データ（holidays-jp）**: 最初は確認環境のネットワーク制限で接続できなかったため、接続を許可してから確かめた。
  梅丘図書館を `lib hours 梅丘 --holiday closed`（祝日休館）にして `libread` を実行すると、holidays-jp から 2026年の祝日
  18日分（11-03 文化の日、11-23 勤労感謝の日などを含む）を取得し、`holidays-2026.json` にキャッシュした。
  2回目の実行はキャッシュを使い、問い合わせなかった。2026-10-30 は祝日ではないので、表示は曜日どおり（開館前 09:00〜19:00）だった。
  祝日当日の表示（休館）は、時刻を差し替えた手順 1 の自動テストで確かめている。
  なお、手順 2 は `--holiday same`（曜日どおり）なので祝日データを使わない。
